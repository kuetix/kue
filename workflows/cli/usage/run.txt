Execute a workflow

Usage:
  kue run <target> [key=value ...] [options]
  kue r   <target> [key=value ...] [options]

<target> is one of:
  - a local .wsl / .swsl file            kue run ./flows/report.wsl
  - a published registry workflow        kue run acme/nightly-close
  - a project directory (auto-detected)  kue run .
  - a single action (transition)         kue run decision/cond.Number value=5 op=gt threshold=3 upper=10

Registry workflows are downloaded from api.kuetix.com, their SHA-256 is
verified against the server, and they are cached under ~/.kue/cache/workflows.
Before executing, kue validates the workflow through the engine and checks
that every action it calls is compiled into this kue binary (see `kue modules`).

Single transition:
  A target shaped `<ns>/<class>.<Method>` runs one linked-in action directly —
  kue wraps it in a generated one-state workflow and executes that. The trailing
  `key=value` pairs become the action's named arguments; use `kue transitions`
  for the parameter list of each action. Values are typed: bare integers,
  floats, booleans and [..]/{..} literals pass through, everything else is a
  string. `--check` reports the signature and runnability without executing.

Options:
  --name, -n       Target (alternative to the positional arg)
  --owner, -O      Registry owner id, to disambiguate a workflow name
  --json, -j       Machine-readable result
  --check, -C      Validate + report runnability only; do not execute
  --force, -f      Execute even if some action modules are missing
  --no-cache, -N   Bypass the local workflow cache
  --host, -H       API host (default: api.kuetix.com)
  --config, -c     Path to config file

Extra `key=value` arguments after the target are passed to the workflow (or,
for a single-transition target, to the action itself).
